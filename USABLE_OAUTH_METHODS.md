# Usable OAuth Methods

This file is the practical surface. Everything here worked in the latest full
run without `OPENAI_API_KEY`, `OPENAI_ADMIN_KEY`, or any `sk-...` key.

## Wrapper

Use:

```bash
cd chatgpt-oauth-bridge
python src/openai_oauth_access.py
```

Import:

```python
from pathlib import Path
from openai_oauth_access import OpenAIOAuthAccess

oauth = OpenAIOAuthAccess()
print(oauth.codex_text("Reply with exactly: ok"))

image_path = oauth.codex_generate_image(
    "A clean OAuth architecture diagram with no readable text.",
    Path("artifacts/example.png"),
)

embedding = oauth.official_embedding("OAuth-only embedding probe")

uploaded = oauth.chatgpt_upload_file(
    Path("artifacts/codex_backend_upload_probe.txt")
)

connectors = oauth.chatgpt_connectors_directory_list()
tools = oauth.chatgpt_apps_tools_list()
```

When importing from outside `src`, put the source directory on `PYTHONPATH`:

```bash
PYTHONPATH=src \
  python your_script.py
```

## Working Methods

- `codex_text(prompt)`: text response through
  `https://chatgpt.com/backend-api/codex`
- `codex_vision(image_path, prompt)`: image input through the same Codex OAuth
  backend
- `codex_generate_image(prompt, output_path)`: image or drawing generation
  through the Codex Responses `image_generation` tool with `gpt-image-2`
- `official_transcribe_audio(audio_path)`: `POST /v1/audio/transcriptions`
- `official_embedding(text)`: `POST /v1/embeddings`
- `realtime_client_secret()`: `POST /v1/realtime/client_secrets`
- `realtime_transcription_session()`: `POST /v1/realtime/client_secrets` with
  `session.type="transcription"`. The local proxy also exposes
  `/v1/realtime/transcription_sessions` as a compatibility alias over the same
  OAuth-accepted client-secret route.
- `realtime_translation_client_secret()`: `POST /v1/realtime/translations/client_secrets`
  for Realtime translation sessions. The latest matrix returned `200`.
- `realtime_webrtc_call_offer(offer_sdp)`: `POST /v1/realtime/calls` with
  Codex-style multipart form-data. The latest deep probe returned `201` and an
  answer SDP. For a real app, pass SDP generated by
  `RTCPeerConnection.createOffer()`.
- `realtime_say_to_pcm(text, output_path)`: Realtime WebSocket audio response
  using the OAuth-created ephemeral key
- `chatgpt_upload_file(path)`: real ChatGPT/Codex backend file upload through
  `POST /backend-api/files`, returning a `sediment://file_...` URI. Signed
  download URLs are omitted by default.
- `chatgpt_plugins_list()`: reads the ChatGPT plugin catalog through
  `GET /backend-api/plugins/list`
- `chatgpt_plugins_featured()`: reads featured Codex plugins through
  `GET /backend-api/plugins/featured?platform=codex`
- `chatgpt_curated_plugins_export()`: reads the curated plugin export pointer
  through `GET /backend-api/plugins/export/curated`; signed URLs are omitted by
  default.
- `chatgpt_connectors_directory_list()`: reads the ChatGPT connector directory
  through `GET /backend-api/connectors/directory/list`
- `chatgpt_connectors_directory_workspace()`: reads workspace connector
  directory metadata through `GET /backend-api/connectors/directory/list_workspace`
- `chatgpt_usage()`: reads the ChatGPT/Codex usage and rate-limit snapshot
- `chatgpt_tasks_list(limit=5)`: reads cloud Codex tasks through
  `GET /backend-api/wham/tasks/list`
- `chatgpt_task_details(task_id)`: reads a cloud Codex task through
  `GET /backend-api/wham/tasks/{task_id}` when the OAuth account has access
- `chatgpt_task_sibling_turns(task_id, turn_id)`: reads Codex sibling attempts
  through `GET /backend-api/wham/tasks/{task_id}/turns/{turn_id}/sibling_turns`
- `chatgpt_environments()`: reads cloud Codex environments through
  `GET /backend-api/wham/environments`
- `chatgpt_environments_by_repo(owner, repo)`: reads repo-scoped Codex
  environments through `GET /backend-api/wham/environments/by-repo/...`
- `chatgpt_agent_identities_jwks_summary()`: reads Codex agent identity JWKS
  metadata through `GET /backend-api/wham/agent-identities/jwks`
- `chatgpt_accounts_check_summary()`: reads account-check shape only through
  `GET /backend-api/accounts/check/v4-2023-04-27`; values are summarized and
  privacy-sensitive fields are not printed.
- `chatgpt_me_summary()`: reads the current ChatGPT user object shape through
  `GET /backend-api/me`; id/email/name values are not returned by the summary.
- `chatgpt_aura_site_status(site_url)`: checks Browser Use/Aura site policy
  metadata through `GET /backend-api/aura/site_status`
- `chatgpt_workspace_plugins_shared()`: reads workspace-shared plugin metadata.
  On the latest deep run it returned `200` with `0` plugins.
- `chatgpt_plugin_detail(plugin_id)` and
  `chatgpt_plugin_skill_detail(plugin_id, skill_name)`: wrappers for the
  source-backed `/ps/plugins/...` detail routes. They need a real plugin id;
  no candidate plugin id was returned by the latest global list.
- `chatgpt_apps_mcp_request(method, params=None)`: sends a JSON-RPC request to
  `POST /backend-api/wham/apps`; `tools/list` is confirmed working.
- `chatgpt_apps_tools_list()`: convenience wrapper for `tools/list`
- `chatgpt_apps_tool_call(name, arguments=None)`: generic Apps MCP tool call.
  The deep runner only called a safe public GitHub repository search.
- `chatgpt_github_search_repositories(...)`: public GitHub repository search
  through Apps MCP `tools/call`
- `official_get(path)` and `official_post(path, ...)`: generic probes for
  newly discovered OpenAI routes

Check optional Platform/Admin credential fallback:

```bash
cd chatgpt-oauth-bridge
python bridge.py fallback
python bridge.py fallback /v1/videos/edits /v1/organization/projects
```

Fallback is disabled unless `OAUTH_BRIDGE_ENABLE_PLATFORM_FALLBACK=1` is set.
When enabled, official OpenAI API requests can be forwarded with
`OPENAI_API_KEY`, `OPENAI_ACCESS_TOKEN`, or `OPENAI_ADMIN_KEY` when a route is
still a boundary or when `prefer` mode intentionally chooses hosted behavior
over local compatibility. `OPENAI_ACCESS_TOKEN` is for official OpenAI
workload-identity-style bearer tokens, not a ChatGPT/Codex OAuth session token.
This is hybrid routing, not OAuth support, and reports never print the key
values. The default mode is `OAUTH_BRIDGE_PLATFORM_FALLBACK_MODE=boundary`: only
blocked official paths forward, and local compatibility routes stay local. Use
`OAUTH_BRIDGE_PLATFORM_FALLBACK_MODE=prefer` or the request header
`X-OAuth-Compat-Prefer-Platform: 1` only when you want exact hosted OpenAI API
behavior before local compatibility. The SDK placeholder value
`oauth-local-proxy` is ignored as a Platform credential.

resource-bound/incomplete paths.

The latest run tried the major official Platform/API Reference families. The
separate surface audit parsed `172` documented OpenAI API paths: `5` direct
official OAuth-verified paths, `167` local/ChatGPT-backend compatibility paths,
`0` API-key/Admin-key required paths, `0` not available in this deployment,

The OpenAI Developer Docs endpoint index also returned `172` paths under
`https://api.openai.com/v1` in the current pass. This matches the local audit
count, but it does not turn local compatibility handlers into hosted Platform
OAuth support. Official spot checks still show `/v1/videos` as API-key-backed
and `/v1/organization/projects` as Admin-API-key-backed.

These hosted Platform behaviors are still not proven as direct ChatGPT/Codex
OAuth support: normal Responses, Chat Completions, hosted legacy Completions,
hosted Images edit/variation API routes, TTS, the official audio translation
route, moderation, official `/v1/files`, official `/v1/uploads`, vector stores,
batches, hosted fine-tuning training and real checkpoint permission changes,
evals, containers, hosted video/Sora rendering and hosted MP4 content, hosted
Assistants/threads, hosted ChatKit sessions/threads, hosted Skills, custom
voices, and real Admin/Usage data or mutations. The bridge covers these as
direct OAuth, ChatGPT-backend, or explicit local compatibility where listed; it
does not turn the ChatGPT/Codex OAuth token into a general Platform credential.

Real hosted Organization, Project, Usage, and Cost resources still require
Platform/Admin credentials. The local bridge now provides sandbox-shaped
metadata and mutation responses so SDK/app flows can be tested without treating
ChatGPT/Codex OAuth as an Admin API credential.

Real hosted video/Sora rendering still requires Platform credentials and
eligible hosted video access. The local bridge now provides video job,
storyboard, remix/edit/extension metadata, character metadata, and JSON content
manifests so SDK/app flows can be tested without claiming hosted MP4 creation.

Hosted containers still require Platform credentials. The local bridge supports
container metadata and file storage compatibility for local app workflows.
Hosted ChatKit still requires Platform credentials. The local bridge supports
session, thread, and item compatibility for local app workflows.
Hosted Skills still require Platform credentials. The local bridge supports
installed Codex skill discovery plus local skill bundle/version compatibility
for local app workflows.
Hosted Conversations still require Platform credentials for the real server
resource. The local bridge supports conversation metadata and item storage
compatibility for local app workflows.

That does not mean these features do not exist. It means the public route
requires documented Platform bearer credentials instead of this ChatGPT/Codex
OAuth token: usually a Platform API key, an Admin API key for admin surfaces, or
an official workload identity federation access token where applicable.
